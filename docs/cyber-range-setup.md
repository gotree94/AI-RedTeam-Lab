# Cyber Range 구성 가이드

## 목적

본인 PC 안에서 교육용 대상만 실습하는 격리된 보안 실험실을 구성한다. 이 문서는 설계 원칙을 설명하며, 실제 네트워크 환경에 따라 설정은 달라질 수 있다.

## 권장 구성

```text
Windows Host
└── VirtualBox
    ├── Kali Linux (분석 워크스테이션)
    ├── Ubuntu Server (테스트용 서비스)
    ├── OWASP Juice Shop / WebGoat (교육용 웹 앱)
    └── Monitoring VM (선택: Wazuh / Suricata / Zeek)
```

## 네트워크 안전 원칙

1. 초기에는 VM 네트워크를 **Host-only** 또는 이에 준하는 격리 네트워크로 설정한다.
2. 취약한 VM을 인터넷에 직접 노출하지 않는다.
3. 포트 포워딩을 사용하지 않는 것을 기본값으로 한다.
4. 실습 전 스냅샷을 생성하고, 종료 후 상태를 복원한다.
5. 테스트 대상 IP/호스트를 문서로 고정하고 범위 밖 주소에 도구를 실행하지 않는다.
6. 호스트와 개인 파일을 공유할 때 최소한의 공유만 허용한다.
7. 로그와 패킷 캡처에 개인정보나 비밀 정보가 포함되지 않도록 한다.
8. AI Agent의 네트워크 접근은 기본 차단하고, 필요한 경우에만 허용된 로컬 대상에 한정한다.

## 구성 요소

| 역할 | 예시 | 주의점 |
|---|---|---|
| 분석 워크스테이션 | Kali Linux | 도구를 최신 상태로 유지하고 격리 네트워크 사용 |
| 테스트 서버 | Ubuntu Server | 테스트용 계정과 데이터만 사용 |
| 취약 웹 앱 | OWASP Juice Shop, WebGoat | 로컬/격리 환경에서만 실행 |
| 패킷 분석 | Wireshark, tcpdump | 캡처 파일에 민감 정보가 없는지 확인 |
| 모니터링 | Wazuh, Suricata, Zeek | 로그 보존 기간과 저장 공간 관리 |
| 기록 | Markdown, Git | 비밀번호, 토큰, 개인 데이터 커밋 금지 |

## 운영 전 체크리스트

- [ ] 대상 시스템을 소유하거나 테스트 허가를 받았다.
- [ ] 테스트 범위와 금지 사항을 문서화했다.
- [ ] VM 네트워크가 격리되어 있다.
- [ ] 스냅샷 또는 복구 방법이 준비되어 있다.
- [ ] 실습용 계정과 데이터만 사용한다.
- [ ] 테스트 결과와 로그를 기록할 위치를 정했다.
- [ ] 외부 시스템으로 향하는 트래픽을 차단하거나 통제했다.

## 종료 절차

1. 실습 프로세스를 종료한다.
2. 테스트 VM을 정상 종료한다.
3. 필요하면 스냅샷으로 복구한다.
4. 로그와 증거를 검토하고 민감 정보를 제거한다.
5. 실습 기록에 방어 대책과 배운 점을 작성한다.
